Day 8 Reflection



The most difficult concept in this course was understanding how to design a system that remains correct when many users make requests at the same time. At first, I focused mainly on making an application work, but system design taught me to think about what happens when traffic increases, requests fail, or two users try to perform the same action simultaneously. I overcame this by breaking the problem into smaller parts, studying concepts such as caching, database indexes, transactions, and load balancing, and applying them to practical examples. Designing TicketHub helped me understand why database transactions and constraints are essential for preventing two customers from buying the same seat.



Based on the feedback and requirements for my QuickNotes capstone, I would improve the architecture documentation by adding more detailed failure scenarios, clearer capacity assumptions, and a stronger explanation of how caching and database replicas affect consistency. I would also improve the implementation with automated tests and a persistent backend rather than relying on a demonstration API. These changes would help connect the design decisions to measurable results.



Next, I want to learn backend development more deeply, especially building REST APIs, working with PostgreSQL, and implementing authentication and authorization. I also want to practise Docker, CI/CD, cloud deployment, monitoring, and load testing. My goal is to become more confident in building applications that are not only functional but also secure, reliable, and able to scale as more people use them.
